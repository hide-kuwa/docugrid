# TAXX 課金・プロダクト境界 — 設計メモ（過剰実装防止）

最終更新: 2026-06-29

## この文書の目的

課金方式は **プロダクトの生死を分ける**。初期の課金設計を誤ると、後から Stripe・契約・UX・会計処理を全面変更することになる。

本書は **いま何を決め、何を実装しないか** を固定する。  
**実装の正本はまだ `backend/services/billing_catalog.py`（DocuGrid 事務所プラン）のみ。** 本書の「将来案」はコードに先走って実装しない。

関連:

## 1. なぜ一度練り直すか

議論の途中で、次が **早すぎる順序** で混ざっていた。

| 問題 | 内容 |
|------|------|
| 料金先行 | ¥10,000・ポイント・前受けの数字から入った |
| 未実装への値付け | Keisan マーケット・ウォレットが無い段階で単価・手数料を想定 |
| 境界未確定 | 「TAXX と DocuGrid は別契約」と言いつつ、利用者・データは DocuGrid 準拠 |

**正しい順序:**

```
プロダクト境界 → 課金に値する価値 → 課金の単位 → 料金表 → Stripe 実装
```

本書は **§2〜§4 までを先に固定** し、§6 の将来案は **ドキュメントのみ** とする。

## 2. プロダクト境界（お金抜き）

### 2.1 三層

| 名前 | 役割 | SSOT（正のデータ） |
|------|------|-------------------|
| **TAXX** | エコシステム・認証シェル・統合ナビ | 認証・`firm_id`・メンバー権限（将来） |
| **DocuGrid** | 資料整理・OCR・正規化・監査 | 顧問先マスタ・指標・PDF・抽出メタ |
| **Keisan** | 計算スタジオ（TAXX 上の機能） | テンプレ定義・実行ログ（根拠は DocuGrid に保存） |

### 2.2 利用者

| 項目 | 方針 |
|------|------|
| 誰が使うか | **税理士事務所とその職員のみ**（一般消費者・無登録公開はしない） |
| 請求単位 | **事務所（`firm_id`）** — 職員個人請求はしない |
| アクセス | **DocuGrid と同じメンバー・顧問先スコープ** |

### 2.3 DocuGrid と Keisan のデータの流れ

```
[DocuGrid] 資料投入 → 正規化（client-master / metrics）
       ↑ read-only 引用
[Keisan] テンプレ実行 → 計算根拠スナップショット
       ↓ 確定1回で保存
[DocuGrid] 監査・DATA・マトリクスから「この数字の根拠」として参照
```

**Keisan は数字の SSOT にならない。** 二重入力は [`integration-port-catalog.md`](integration-port-catalog.md) の禁止パターンに従う。

### 2.4 契約の考え方（未確定・要議論）

| 案 | 内容 | メリット | デメリット |
|----|------|----------|------------|
| **A. 1契約** | TAXX 月額に DocuGrid 本体を含む | 請求・説明が単純 | 「別プロダクト」感は弱い |
| **B. 2契約** | DocuGrid と TAXX（Keisan）を別 Subscription | プロダクト分離が明確 | 運用・UI・解約が複雑 |
| **C. 段階** | 当面 A、顧客が増えたら B を検討 | **過剰実装を避けられる（推奨）** | 将来の請求分離コスト |

**現時点の推奨:** 対外説明は **TAXX**、実装・SSOT 表記は **DocuGrid**（[`product-naming.md`](product-naming.md)）。課金は **事務所あたり1本の Subscription** から始める。

## 3. 課金に値する価値（優先順位）

お金を払う理由を **機能リストではなく瞬間** で書く。

| 優先 | 価値の瞬間 | 主な担い手 |
|------|------------|------------|
| **P0** | 資料を入れるだけでマスタ・指標が埋まる | DocuGrid |
| **P1** | 正規化データを引用し、根拠付き試算が一発で出る | Keisan |
| **P2** | 他事務所の優秀なテンプレを使える（品質・時間短縮） | Keisan マーケット |
| **P3** | AI が実コストをかける分だけ従量 | TAXX AI |

**課金の重心:** まず **P0 + 月額**。P2 が動き出すまで **ポイント・前受け・Connect 分配は実装しない**。

## 4. いま決めること / 保留すること

### 4.1 確定（方針レベル）

| # | 決定 |
|---|------|
| 1 | 請求単位 = **事務所** |
| 2 | 利用者 = **DocuGrid 準拠**（事務所メンバー） |
| 3 | **無料枠は当面なし**（トライアルは別途検討可） |
| 4 | **月額 ¥10,000** をプラットフォームのたたき台（税別・要最終確認） |
| 5 | **実コスト系（AI）のみ従量** — 既存 `ai_usage_service` の延長 |
| 6 | Keisan **社内テンプレ** = 月額の範囲（ポイント消費なし） |

### 4.2 保留（マーケット稼働まで実装しない）

| 項目 | 理由 |
|------|------|
| ポイントウォレット・前受けチャージ | 他所テンプレの取引が無いと意味が薄い |
| テンプレ1回あたりの pt 単価 | 公開テンプレの相場が未観測 |
| Stripe Connect による作者分配 | マーケット Phase 2 |
| TAXX / DocuGrid **別 Subscription 2本** | 顧客ゼロ段階では運用負債 |
| 顧問先 ¥100/社を TAXX に含めるか | 現行 `billing_catalog` との整合を別 PR で |

### 4.3 現行コードとの関係

| 場所 | 状態 |
|------|------|
| `billing_catalog.py` | DocuGrid: ¥10,000 + ¥100/顧問先/月（**実装済み SSOT**） |
| `stripe_connect_service.py` | 営業パートナー報酬（Keisan 作者分配とは別用途） |
| 本書 §6 | **設計メモのみ。コードに写さないこと** |

## 5. Keisan — どんなサイト・体験にするか（話し合い用）

### 5.1 Keisan は「何でも計算するサイト」ではない

弥生シミュレーター・keisanbox・国税庁作成コーナーのような **一般向け無料計算機** とは別物。

| 一般向け計算サイト | TAXX Keisan |
|--------------------|-------------|
| 誰でもアクセス | **事務所職員のみ** |
| 手入力が中心 | **DocuGrid 正規化データを引用** |
| 結果は画面だけ | **計算根拠を DocuGrid に保存**（監査可能） |
| テンプレは運営固定 | **事務所・職員がテンプレを作り、公開できる** |

### 5.2 UI の分離（同リポ・別システム）

```
┌─ TAXX シェル（共通ヘッダ）──────────────────────┐
│  [TAXX]  [DocuGrid]  [Keisan]  [設定]  事務所名   │
├──────────────────────────────────────────────────┤
│  DocuGrid 画面          │  Keisan 画面            │
│  マトリクス・PDF・DATA    │  テンプレ・実行・履歴    │
│  （既存 UI）             │  （別レイアウト・軽量）  │
└──────────────────────────────────────────────────┘
```

- **同じリポジトリ**（AI・認証・API の文脈共有）
- **Route Group で UI を完全分離**（PDF.js 等を Keisan に載せない）
- 左上ロゴ / タブで **DocuGrid ↔ Keisan** を切り替え

### 5.3 Keisan 内の主要画面（案）

| 画面 | 役割 |
|------|------|
| **ホーム** | 最近使ったテンプレ・社内おすすめ・（将来）マーケット入口 |
| **テンプレート** | 一覧・検索・カテゴリ（法人税・株価・賃上げ促進…） |
| **エディタ** | 変数・式・注釈・参照元（DocuGrid フィールドピッカー） |
| **実行** | 顧問先・期間を選び、引用値を確認してから計算 |
| **履歴** | 実行ログ・DocuGrid への保存済み根拠へのリンク |

### 5.4 テンプレの公開範囲（課金と直結）

| 範囲 | 誰が使う | 課金（方針） |
|------|----------|--------------|
| `internal` | 同一事務所のみ | **月額に含む**（ポイント不要） |
| `marketplace` | 他事務所 | **利用ごとに課金**（将来: ポイント） |

「公開する」= **marketplace に出す** と定義すると、社内無料・他所有料の線引きが明確。

### 5.5 参考にするイメージ（雰囲気）

| 参考 | 取り入れる | 取り入れない |
|------|------------|--------------|
| スプレッドシートの「計算シート」 | 変数・式・注釈・版管理 | Excel 全面再現 |
| Notion テンプレギャラリー | 事務所内共有・複製 | 一般公開 |
| GitHub | 版・作者・fork（社内） | 全世界 OSS |
| 税理士向けチェックリスト | 手順同期・根拠残し | — |

**Keisan のトーン:** 派手なマーケ LP ではなく、**実務室で毎日開く業務ツール**（落ち着いた UI・数字と出所が並ぶ）。

### 5.6 議論したい未決事項（Keisan）

1. **テンプレ作者** — 職員個人名義か、事務所名義か（著作・収益の帰属）
2. **実行の単位** — 1顧問先1回か、期間ごとか、バッチか
3. **マーケットの品質** — 公開前に所内承認のみか、プラットフォーム審査か
4. **免責** — 試算・根拠整理用であることの表示（利用規約 + テンプレごと）
5. **最初の1本** — どのテンプレから PoC するか（例: 定款・謄本由来の資本金チェック、別表四照合）

## 6. 将来の課金モデル（ドキュメントのみ・未実装）

マーケットで他所テンプレの取引が発生してから検討する **案**。

### 6.1 ポイント制（案）

| 要素 | 案 |
|------|-----|
| 1 pt | ¥1 相当（税別）で固定 |
| 月額 ¥10,000 | 毎月 **N pt 付与**（他所テンプレ専用・N は未確定） |
| 社内テンプレ | pt 消費なし |
| マーケット利用 | 公開者設定 pt / 回をウォレットから控除 |
| 不足時 | 追加購入（前受け）— 閾値・自動チャージは後回し |
| 分配 | プラットフォーム手数料後、公開者へ（Connect は Phase 2） |

### 6.2 実装トリガー（これが揃うまで §6 をコードにしない）

- [ ] Keisan 社内テンプレの実行・DocuGrid 保存が動いている
- [ ] `marketplace` 公開テンプレが **2事務所以上** で実際に使われた
- [ ] 利用規約・免責・テンプレ審査の方針が文書化された
- [ ] 会計上の前受け金・ポイント有効期限の方針（顧問先と合意）
