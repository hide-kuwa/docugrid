# マイナンバー（特定個人情報）の取扱い

**要約:** DocuGrid は、個人番号を含む書類を **一般資料と分離した暗号化領域（SPI レーン）** に保管します。Google Drive への自動ミラーと AI 分類の対象外とし、専用権限・監査ログ・保存期間後の廃棄を前提にしています。

対象: 導入検討中の所長・HP／信頼情報ページの執筆者・運用担当  
法的助言ではありません。運用の最終判断は各事務所の取扱規程と顧問弁護士／専門家に従ってください。  
正本ガイドライン: [特定個人情報の適正な取扱いに関するガイドライン（事業者編）](https://www.ppc.go.jp/files/pdf/2405_my_number_guideline_jigyosha.pdf)（個人情報保護委員会）

スタッフ向け手順: [help/my-number.md](./help/my-number.md)

## HP 向け（そのまま使える短い説明）

### 見出し案

**マイナンバー関連書類も、分離・暗号化して守ります**

### 本文案（短）

DocuGrid では、個人番号を含む書類（源泉徴収票・扶養控除等申告書など）を、通常の顧問先資料とは **別の保管レーン** に置きます。ディスク上は暗号化し、権限のある職員だけが復号して閲覧できます。Google Drive への自動コピーや、外部 AI への分類送信は行いません。保存が不要になったあとは、期間に沿って削除できる設計です。

### 3点まとめ（箇条書き用）

1. **分離保管** … 一般 PDF とは別パス（事務所単位の暗号化領域）
2. **最小権限** … `my_number.view` / `my_number.manage` がある人だけ閲覧・管理
3. **外部に出さない** … Drive ミラーなし・AI 分類なし・顧問先ポータル共有なし

## システム上の処理（技術の要約）

| 項目 | DocuGrid のやり方 |
|------|-------------------|
| 保管場所 | `storage/{firm_id}/spi/{id}.enc`（平文 PDF を置かない） |
| 暗号化 | 保管時に Fernet（AES + 改ざん検知）。鍵は `DOCUGRID_SECRET_ENCRYPTION_KEY` 由来の **SPI 専用派生** |
| アクセス | JWT の事務所境界＋顧問先担当＋ `my_number.*` 権限 |
| Drive | **ミラーしない**（持ち出し・目的外共有のリスクを下げる） |
| AI / OCR 外部送信 | **対象外**（番号入り PDF をモデルに送らない） |
| 顧問先ポータル共有 | **禁止** |
| 保存期間 | 既定 7 年（税関係書類の保存を意識した既定。事務所で短縮・延長可） |
| 廃棄 | 期限経過後の一括 purge、または明示 purge（復元不能削除＋監査） |
| 監査 | アップロード・ダウンロード・削除を `audit_events` に記録 |
| 表示 | API メタデータのファイル名などから 12 桁らしき数字をマスク |

API（内部）:

- `GET /api/spi/policy` … 上記方針の機械可読サマリ（秘密情報なし）
- `POST/GET/DELETE /api/spi/documents...` … 専用レーンの入出力
- スロットアップロードで `contains_individual_number=true` … マトリクス上でも同じ暗号化レーンへ

## 設計原則（番号法に沿った型）

1. **目的限定** … 税・社保など認められた事務の範囲で扱う。CRM 用 ID や学習データに番号を載せない  
2. **分離** … 特定個人情報ファイルを一般資料と混ぜない  
3. **最小権限** … 事務取扱担当者に限定（ロールで付与）  
4. **期限付き廃棄** … 法令の保存期間経過後は削除を前提にしたシステム  

DocuGrid 運営が SaaS として預かる場合、顧客事務所との **委託契約・監督・再委託条件** は契約書側でも明示してください（Drive / クラウド基盤の再委託を含む）。

## まだ「運用で補う」こと

- 紙の原本・FAX・メール添付の取扱規程（物理・人的措置）
- 誰を事務取扱担当者にするかの事務所内決定
- 漏えい時の報告フロー（社内＋必要に応じて個人情報保護委員会）
- 本番の鍵管理（`DOCUGRID_SECRET_ENCRYPTION_KEY` を十分な長さの乱数に）
