# CRM パック構想 — 汎用コア × 保険／不動産 × Doc 永続 UI

最終更新: 2026-08-08  
ステータス: 構想＋UI 骨格（データ API 未接続）

DocuGrid に **汎用 CRM** を載せ、売り物として **保険**・**不動産** パックを乗せる方針。  
既存の資料マトリクス（特に **永続**）から、保有・提案・進捗案件を同じ顧問先視線で見られるようにする。

関連: [`platform-packs-vision.md`](platform-packs-vision.md)、[`ssot-normalization.md`](ssot-normalization.md)、[`auth-tenancy-design.md`](auth-tenancy-design.md)、ヘルプ [`help/crm-perm.md`](help/crm-perm.md)

---

## 1. ゴール

1. **商材非依存の CRM コア**（Party / Deal / Activity / Offer）を `firm_id` スコープで持つ。
2. **保険・不動産は定義パック**（ステージ・商品・必要スロット）として載せ替え可能にする。
3. Doc の左ドラムは増やさない。**永続の中の横タブ**で状態を切り替える。
4. 証跡 PDF は従来どおりスロット。商談の真実は Deal。紐づけはサーバ側。

---

## 2. UX 決定（2026-08-08）

```
左（縦）: データ | 永続 | R8 | R7 …
                    ↓ 永続を選んだときだけ
上（横）: [ 資料 ] [ 保有 ] [ 提案 ] [ 案件 ]
```

| 横タブ | 役割 |
|--------|------|
| **資料** | いまの永続スロット全体（既存マトリクス） |
| **保有** | 契約中の保険など「入っている」一覧＋証券 PDF への導線 |
| **提案** | 提案中の見積・設計・提案書 |
| **案件** | この顧問先の進捗中 Deal（保険も不動産も同じ箱） |

- 左に「保険」「案件」行は **作らない**（見やすさ・ドラムの単純さ優先）。
- 年度（R8 等）では横タブは出さない（永続専用）。
- パック未導入時はタブは骨格表示・中身は空／プレビューでよい。

UI 骨格: `frontend/src/features/crm/`（`PermCrmStrip` / `PermCrmPanel`）

---

## 3. データモデル（コア）

すべて JWT の `firm_id`。顧問先は任意リンク。

| エンティティ | 概要 |
|--------------|------|
| **Party** | 個人／法人の連絡先。`client_id` に紐づけ可（顧問先≠見込みもあり） |
| **Deal** | 1 商談。`pack_id`（insurance / real_estate / …）、ステージ、担当、任意 `client_id` |
| **Activity** | 通話・訪問・メモ・メールログ |
| **Offer / line** | 商談内の商品行（保険商品・物件など） |
| **Deal↔Slot** | 提案セット／保有セットの資料スロットへのリンク |

状態の見方:

- **保有** ≈ Deal `won`（または `held`）＋保有用スロット  
- **提案** ≈ open Deal の提案資料ビュー  
- **案件** ≈ open Deal リスト／簡易カンバン  

フロントのフィルタだけで「保有フォルダ」を増やさない。

---

## 4. パック（保険・不動産）

[`platform-packs-vision.md`](platform-packs-vision.md) と同じ層:

```
firm override > installed pack > global > built-in
```

パックに含めるもの（例）:

| 資産 | 保険例 | 不動産例 |
|------|--------|----------|
| ステージ定義 | ヒアリング→設計→申込→成立 | 反響→内見→申込→契約→決済 |
| 商品／物件スキーマ | 生保・損保カテゴリ | 物件・売主買主ロール |
| 必要スロット | 証券・約款・提案書 | 重説・契約書 |
| アラート | 満期・更新 | 決済日 |

コード分岐は `pack_id` によるラベル・必須項目の差に留める。

## 5. 実装フェーズ

| Phase | 内容 | 状態 |
|-------|------|------|
| **C0** | 構想メモ＋永続横タブ UI 骨格 | **いま** |
| **C1** | Deal / Party API（SQLite、firm スコープ、テスト） | 未 |
| **C2** | 保有／提案を Deal 状態＋スロットリンクで埋める | 未 |
| **C3** | 保険パック（ステージ・スロット定義）1 本 | 未 |
| **C4** | 不動産パックを同じ枠で追加 | 未 |
| **C5** | 満期アラート・追客・パック配布 | 後 |

---

## 6. セキュリティ

- すべての CRM API で `firm_id` 一致。`client_id` 付きなら `authorize_client_access`。
- パック export に顧客・商談の実データを入れない（定義のみ）。
- 画面フィルタは UX のみ。一覧・取得はサーバで絞る。

---

## 7. やらないこと（初期）

- 左ドラムに商材行を増やす  
- 保険専用アプリ／不動産専用アプリの分岐  
- Salesforce 互換を最初から狙う  
- 顧問先マスタの二重管理（Party は拡張／リンク）
