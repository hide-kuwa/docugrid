# 初回データ整理（ZIP 一括取り込み）

**要約:** 設定 → 顧客マスタで ZIP を投入すると、フォルダパス・ファイル名から顧問先・期間・書類種別を推定し、確信度が高いものはマトリクスへ自動配置します。顧問先の紐づけ学習は事務所内のみ。**PROLEXT税理士法人**の確定から書類種別フォルダ名だけ全事務所が参照します（顧問先 ID は共有しません）。

## 誰向け

- 本番移行・初回オンボーディングで、旧 PC やバックアップ ZIP をまとめて DocuGrid に載せたいスタッフ
- 顧客マスタ CSV を先に取り込んだあと、資料 ZIP を流し込みたい担当者

## 手順

1. **顧客マスタ CSV** を取り込み・保存（顧問先名の照合精度が上がります）
2. 設定 → **顧客マスタ** の **初回データ整理（ZIP 一括）** で ZIP を選択
3. 処理完了後、**要確認キュー**で同じ顧問先・期間・スロットにまとめて確定

フォルダ例: `テスト商事/R8/請求書/foo.pdf` → 顧問先名・R8 期・書類種別を推定します。

## おすすめの二段階（無料で試す → 必要なフォルダだけ Vision）

1. **ZIP 取り込み**で「**初回は Vision なし**」にチェック → パス名・ルール・カタログだけで振り分け（整理トークンほぼゼロ）
2. 要確認キューで **どこまで自動配置されたか** を確認
3. 直したいフォルダだけ  
   - 行をチェックして **「選択を Vision で再分類」**  
   - または **フォルダ接頭辞**（例: `株式会社A/R8`）を入れて、その配下だけ再分類
4. 提案が良くなったら **一括確定**

再分類は **要確認の提案を更新するだけ**（自動でマトリクスへ入れない）。確定は人が行います。

## 自動配置の条件

- 顧問先 ID がパスまたは過去の確定から特定できる
- 期間（例: `year:1` = 画面の R8 列）がパスから読める
- 書類種別の確信度が **0.6 以上**（画面に表示の閾値と同じ）

## 整理用トークン（月次 AI 枠とは別）

- 残高は **整理用ウォレット** から減算（顧問先ごとの月次枠は使わない）
- 価格はサーバー env で設定（本番は `.env` / ホストの環境変数）

| 環境変数 | 意味 | 例 |
|----------|------|-----|
| `MIGRATION_YEN_PER_PACK` | 販売パック価格（円） | `10000` → ¥10,000/パック |
| `MIGRATION_TOKENS_PER_100_YEN` | ¥100 あたりのトークン数 | `10000` → ¥100 = 1 万トークン |
| `MIGRATION_INCLUDED_TOKENS` | 新規 firm の初期付与（未設定時は 1 パック分） | `200000` |
| `MIGRATION_ESTIMATE_TOKENS_PER_PDF` | ZIP 見積の PDF 1 件あたり想定 | `400` |

**換算:** 1 パックのトークン数 = `MIGRATION_YEN_PER_PACK × MIGRATION_TOKENS_PER_100_YEN / 100`  
例: ¥10,000 × 10000/100 = **100 万トークン/パック**

画面では ZIP 選択時に **見積トークン・円** を表示し、ジョブ完了後に **実消費** と差分を表示します。

## 保存する情報（個人情報の取り扱い）

| 保存する | 説明 |
|----------|------|
| PDF 本体 | 当該事務所の storage 内のみ |
| ZIP 内パス・ファイル名 | 要確認画面での確認用 |
| 分類メタ | 書類種別・確信度・エンジン名など |
| フォルダ名エイリアス（書類種別） | PROLEXT 確定時のみ全事務所共有（顧問先 ID は含まない） |

| 保存しない／共有しない | 説明 |
|------------------------|------|
| 他事務所への顧問先データ共有 | client_id・顧問先名の横断学習 |
| OCR/Vision 全文の恒久保存 | 分類処理中の一時利用が基本 |

## 精度が上がる範囲

- **この事務所内:** フォルダ名→顧問先 ID のエイリアス（確定のたびに蓄積）
- **全税理士事務所（書類種別のみ）:** **PROLEXT税理士法人**（`firm_prolext`、env `MIGRATION_GLOBAL_LEARNING_FIRM_ID` で変更可）の確定から、書類カテゴリフォルダ名→書類種別を全事務所が参照
- **共有しない:** 顧問先名・client_id・PDF 本文

## できないこと

- ZIP 以外の形式の一括（個別 PDF はマトリクスの自動振り分けを利用）
- 100% 無人での完全自動（要確認キューが前提）
- Drive 上のフォルダを直接スキャン（ZIP またはマトリクス経由）

## 失敗時

| 症状 | 対処 |
|------|------|
| 要確認が多い | 顧客マスタ名を正式名称に合わせる。フォルダ名を顧問先名に近づける |
| 整理用トークン不足 | 運用担当に整理パック追加を依頼 |
| 自動配置されない | 確信度が閾値未満。キューで手動確定するとエイリアス学習される |

## Drive の容量がいっぱいのとき

- **ZIP 整理は DocuGrid サーバーに先に載る**ため、Drive に空きがなくても取り込みは進められます  
- 旧 Drive フォルダは移行完了まで **削除しない**（`00_移行前アーカイブ` などにまとめて読み取り専用がおすすめ）  
- マトリクスで確認後、重複削除・外付け退避・プラン見直しで Drive を空ける  
- 空きができたら Drive 連携 ON → **整理済み PDF だけ**ミラー
