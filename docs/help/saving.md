# 保存先について

要約: ログイン保存はサーバー（と任意で Google Drive）。ゲストやダウンロードは端末のみ。ブラウザに勝手には溜まりません。LP向けのやさしい全体説明は [storage-story.md](./storage-story.md)。Drive 接続は [google-drive.md](./google-drive.md)。

対象: 所長・運用担当・スタッフ（「データはどこ？」が気になる人）

---

## 結論（3行）

- **ログインして保存／格納した資料** → DocuGrid の **サーバー上**（開発中はホスト PC の `backend/storage/`）  
- **Google Drive 連携が ON** → 事務所 Drive にもミラー（正式保管の置き場）  
- **ゲスト `/pdf` やダウンロードボタン** → その人の **端末** に落ちるだけ  

ユーザーのブラウザに勝手に溜まるアプリではありません。

---

## イメージ

```
社員A・社員Bのブラウザ  ──API──→  【サーバー】storage / DB
                              └─（任意）→ Google Drive

ゲスト /pdf ・「ダウンロード」──→ その人の PC / スマホだけ
```

---

## 操作ごとの行き先

| 操作 | 行き先 | 他メンバーは見える？ |
|------|--------|----------------------|
| Doc スロットへ投入・格納 | サーバー（＋任意 Drive） | 同じ事務所・権限があれば見える |
| ログイン後 PDF 面から DocuGrid へ格納 | 同上 | 同上 |
| ビューアの **作業保存** | サーバー上の版 | フロー・権限による |
| **ダウンロード** | 端末のみ | いいえ（渡さない限り） |
| ゲスト `/pdf` の編集 | 原則端末／タブ内。サーバー保存なし | いいえ |

---

## 「保存したのに他の人に出ない」チェックリスト

1. 相手も **同じ事務所** でログインしているか  
2. **同じ顧問先**・**同じ期（R8 など）** を開いているか  
3. 自分は **ダウンロードだけ** していないか  
4. 画面上で **格納／作業保存が成功**したメッセージや表示があるか  
5. 権限（担当外顧問先など）で相手から見えない設定になっていないか  

それでもダメなら、再現手順をメモしてサポート（メール CS）へ。→ [support.md](./support.md)

---

## 本番では

本番ホスト上のディスク（またはそれに相当するストレージ）が `storage` の役割になります。  
Drive はバックアップ／正式保管。**認可は DocuGrid 側が正**です（Drive の共有リンクを正にしない）。

設定ミスで危険になりうる点（パスワードログインを本番で残す等）は運用チェックリストで潰します。  
技術詳細: `docs/security-status.md`、`docs/google-drive-storage-strategy.md`

---

## よくある誤解

- 「ブラウザにキャッシュされていれば事務所保管」→ **違う**  
- 「ゲストで編集したから Doc に残る」→ **残らない**（[guest-pdf.md](./guest-pdf.md)）  
- 「Drive にあれば DocuGrid の権限は不要」→ **不要にしない**（認可はアプリ側）
