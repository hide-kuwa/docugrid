# 監査フロー（資料の確認・承認）

要約: Doc のビューア（フル画面）では、注釈したあとに **作業保存 → 承認依頼 → 監査開始 → 承認／差戻し** という流れがあります。権限によって見えるボタンが違います。PDF だけの簡単画面（ダウンロード中心）ではこのフローは出ません。

対象: 担当スタッフ・承認者（所長など）

---

## いつ使う画面か

**Doc** のスロットから資料を開き、監査・承認用のヘッダーが出ているときです。  
レールの **PDF**（シンプル）やゲスト `/pdf` では、主にダウンロード／格納だけで、監査ボタン一式は出ません。

---

## 状態のイメージ

```
下書き ──作業保存──→ （版が残る）
   │
   ├─承認依頼──→ レビュー待ち
   │
   └─監査開始──→ 監査中 ──┬─承認──→ 完了系
                         ├─差戻し──→ 修正へ
                         └─中断・保存──→ 監査中のまま一時退避
```

表示名は権限・事務所設定で多少変わります。画面上のボタン名を正としてください。

---

## よくある操作

1. 資料を開き、必要なら **編集を開始** して注釈  
2. **作業保存** … 承認なしで版を残す（下書きの区切り）  
3. レビューが必要なら **承認依頼**  
4. 監査担当が **監査開始**（2画面照合などが使いやすくなることが多い）  
5. 問題なければ **承認**／修正が必要なら **差戻し**（理由入力）  
6. 途中で止めるときは **中断・保存**

未保存の変更件数はヘッダー付近に出ることがあります。保存前に閉じないように注意してください。

---

## 権限について

- 注釈・作業保存と、最終承認では必要な権限が違います  
- ボタンが灰色／無いときは、自分の役割ではその操作ができない可能性があります  
- わからないときは事務所の管理者に確認（将来は AI サポート → メール CS）

---

## できないこと・注意

- ゲスト PDF やシンプル PDF 画面だけでは正式な監査履歴は残らない想定です  
- 差戻し理由は後から見返すことがあるので、具体的に書いてください  
- ステータスの正式名は画面表示を正とします（内部コード名はヘルプに出しません）  

---

## うまくいかないとき

| 症状 | まずやること |
|------|----------------|
| 承認依頼ボタンが無い | 未保存の変更、権限不足、またはシンプル PDF／ゲスト画面を開いている |
| 差戻し後に戻れない | Doc スロットで最新版を開き直し、指摘どおり修正 → 再依頼 |
| 2画面照合が使えない | 監査開始前／権限／事務所設定。まずは単画面で注釈と作業保存 |
| クライアント共有が見えない | 共有機能が OFF、または対象外の資料種別 |

詳細な権限設計は事務所管理者へ。ユーザー窓口は [support.md](./support.md)。
