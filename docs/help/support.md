# 困ったとき（サポートの流れ）

対象: 全ユーザー

DocuGrid でわからないこと・不具合があったときの、公式の流れです。

---

## おすすめの順番

1. **画面のガイド（チュートリアル）**  
   左レールの **ヘルプ** にマウスを乗せ、**ガイド** から押すべき場所が光る短い説明をやり直せます。

2. **ヘルプ記事を読む**  
   同じパネルの **ヘルプセンター**、またはアプリ内 `/help`。  
   例: [overview.md](./overview.md) / [workspace.md](./workspace.md) / [faq.md](./faq.md)

3. **サポートチャット（S2〜S3）**  
   同じパネルの **サポート** で質問できます。サーバが `docs/help` を検索して答えます。  
   解決しないときは **CS チケット**（メール優先）。SMTP 未設定でも事務所スコープでチケットは保存されます。  
   - 使い方 → 近いヘルプ記事・ガイドを案内  
   - **不具合** → チケット作成（いつ／画面／操作／メッセージ）  
   - 解決できない → **カスタマーサポート（CS）へ（メール優先）**

4. **CS（人のサポート）**  
   - **基本はメール**（経緯が残る・確実）  
   - **メールだけでは難しいときだけ電話**（業務が止まっている等）

### 管理者向け（メール送信）

環境変数（任意）:

- `DOCUGRID_SUPPORT_INBOX_EMAIL` … CS 受信箱  
- `DOCUGRID_SUPPORT_SMTP_HOST` / `PORT` / `USER` / `PASSWORD` / `FROM` / `TLS`  

未設定時はアプリ内 SQLite（`backend/storage/support_tickets.db`）に保存のみ。Mailto フォールバックあり。

電話番号を最初から探す必要はありません。必要なときは CS からメールで案内します。  
運用側の詳細: [support-ops.md](./support-ops.md)

---

## 不具合を伝えるときに書いてほしいこと

- いつ頃起きたか  
- どの画面か（Doc / PDF / カルテ など）  
- 何をしようとしていたか  
- 画面に出たメッセージ（あればそのまま）  
- 毎回起きるか / 一度だけか  

AI チャットが使えるようになったら、チャットが聞き取りを手伝います。
